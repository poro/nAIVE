Install in One Line

Homebrew builds the CLI and the standalone player from the release source. Prebuilt player and demo-app downloads for Apple silicon are on GitHub Releases.

terminal
$ brew install poro/tap/naive
$ naive init my-game && cd my-game
$ naive edit     # open the AI scene editor (MCP socket)
$ naive test     # run Lua playtests headlessly, no GPU
$ naive build    # ship a standalone .app or Linux bundle
$ naive demo     # browse the 19 built-in demos
Core Features

AI-Native by Design

Every architectural decision in nAIVE was made to enable AI collaboration. Not as a plugin — as the foundation.

⚡

Sub-Second Hot-Reload

Shaders in <200ms, scenes in <100ms, scripts in <50ms. Zero frame drops. State preserved across reloads. 100x faster than Unity/Unreal.

📄

YAML-Driven Everything

Scenes, render pipelines, materials, input bindings — all human-readable YAML. Git-friendly, diffable, and trivially generatable by LLMs.

🧠

MCP Command Interface

20 typed tools over a Unix socket: spawn and edit entities, run Lua, capture frames and diff screenshots, run tests, benchmark, undo. Claude, GPT, or your own agent drives the running engine.

🧪

Headless AI Playtesting

The simulation lives in its own GPU-free crate, so tests run the same construction, physics and Lua as the game — no GPU, no window. Fixed timestep, supervised runs with hard deadlines.

🔺

Declarative Render DAG

One YAML file defines the deferred PBR pipeline: shadows, G-buffer, Gaussian splats, lighting, bloom, tonemap, FXAA. Topological sorting and cycle detection built in.

🌐

Gaussian Splats (3DGS)

First-class engine feature. PLY loading, depth compositing with mesh geometry, hardware-accelerated rendering. Not a plugin — built in.

💥

Dynamic Physics

entity.spawn_dynamic() for runtime physics bodies. Physics materials with restitution/friction, CCD for fast projectiles, impulse/force/velocity API.

🎮

19 Embedded Demos

Run naive demo to browse and launch any of 19 demos across 6 categories — no downloads needed. Getting Started, Physics, Visual, Gameplay, Stress Test, Showcase.

🐜

GPU Swarms

50,000 units moving, separating, path-finding on flow fields and fighting in GPU compute — about 1,000 fps on an M4 Max. Driven from Lua with the swarm API.

🌗

Shadows & Sky Lighting

Cascaded shadow maps, frustum culling, and an optional sky with image-based lighting — all from the YAML pipeline and scene settings.

📦

Standalone Games

naive build packages a macOS app or Linux bundle with a player built without the shader compiler; shaders are precompiled to WGSL.

🛡️

Sandboxed Lua

Every script call runs under CPU, memory and time limits — including pattern matching and library calls — so agent-written code cannot freeze the editor.

Self-Improving Engine

Dev Feedback Loop

Every AI-built game is a test case. Zero-cost feedback. Structured, not narrative.

Every naive init project includes a structured dev.log template. AI agents maintain it throughout development (instructed via CLAUDE.md), recording what worked, what broke, and what's missing. When done, naive submit-log posts it as a GitHub Issue with the dev-log label. The engine agent reads all dev.logs worldwide and evolutionarily improves the engine. The more games built, the better the engine gets.

pipeline.yaml
version: 2
settings:
  vsync: true
  hdr: true

resources:
  - name: gbuffer_albedo
    format: rgba8
    size: viewport
  - name: gbuffer_normal
    format: rgba16f
    size: viewport
  - name: hdr_buffer
    format: rgba16f
    size: viewport
  - name: bloom_buffer
    format: rgba16f
    size: viewport/2

passes:
  - name: geometry_pass
    type: rasterize
    shader: builtin:gbuffer
    outputs:
      color: gbuffer_albedo
      normal: gbuffer_normal

  - name: lighting_pass
    type: fullscreen
    shader: builtin:deferred_light
    inputs:
      gbuffer_albedo: gbuffer_albedo
      gbuffer_normal: gbuffer_normal
    outputs:
      color: hdr_buffer

  - name: tonemap_pass
    type: fullscreen
    shader: builtin:tonemap
    outputs:
      color: swapchain
Architecture

Built Different

A lean, modern stack designed for speed, composability, and AI-native workflows.

Runtime Core — Rust

  • WebGPU (wgpu 30) — Metal/Vulkan/DX12 backends
  • Entity Component System (hecs) — data-oriented design
  • Rapier3D physics — rigid bodies, character controllers
  • Kira spatial audio — 3D sound, doppler, attenuation
  • Slang shaders, precompiled to WGSL for shipping
  • GPU-free naive-sim crate shared by game and tests

Data Layer — YAML + glTF

  • YAML for scenes, pipelines, materials, input, events
  • glTF 2.0 mesh loading with procedural fallbacks
  • PLY Gaussian splat loading with SH extraction
  • Git-friendly, diffable, AI-generatable
  • No binary blobs, no proprietary formats

Scripting — Lua 5.4

  • Per-entity sandboxed environments
  • Lifecycle hooks: init, update, on_event, on_reload
  • Sandboxed: CPU, memory and time limits per call
  • Hot-reload preserves entity self tables
  • Health/damage, projectile spawning, entity.spawn_dynamic()

AI Integration — MCP

  • 20 typed tools over a Unix socket
  • Frame capture, screenshot diff, undo, benchmarks
  • Headless test runner — no GPU required
  • CI/CD ready with GitHub Actions
  • Built for Claude Code, Cursor, AI agents

Dev Feedback — Self-Improving

  • Structured dev.log in every project
  • AI agents maintain logs during development
  • naive submit-log → GitHub Issues with dev-log label
  • Engine agent reads all logs, improves engine
  • Virtuous cycle: more games = better engine

Demo System — 19 Embedded

  • All demos compiled via include_str!()
  • 6 categories: Getting Started → Showcase
  • Zero downloads — run any demo instantly
  • Each demo exercises specific engine features
  • Living documentation and regression tests
